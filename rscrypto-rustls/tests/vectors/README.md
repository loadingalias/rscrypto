# TLS and QUIC vectors

The three `rfc*.txt` files contain published octet strings from
[RFC 8448 §3](https://www.rfc-editor.org/rfc/rfc8448.html#section-3) and
[RFC 9001 Appendix A](https://www.rfc-editor.org/rfc/rfc9001.html#appendix-A),
retrieved on 2026-10-11. No expected cryptographic output was generated by rscrypto.
The OpenSSL-generated credentials in `credentials/` have their own [provenance](credentials/README.md).

`rfc8448.txt` retains every labeled octet string from the simple 1-RTT trace,
including its key schedule, handshake messages, traffic keys, encrypted records,
Finished values, resumption secret, application traffic, and closing alerts.
`rscrypto-rustls/src/tests/records.rs` executes all symmetric operations in sequence. It does not claim to
reproduce RSA signing or a live rustls handshake.

The QUIC files contain the CRYPTO frames, unprotected headers, and complete
protected Initial packets from A.2 and A.3. `rscrypto-rustls/src/tests/symmetric.rs` and
`rscrypto-rustls/src/quinn/tests.rs` pad the client payload to the specified 1,162 bytes.
The smaller A.4 Retry and A.5 ChaCha20 vectors are embedded directly in the `rfc9001_retry_*` and `rfc9001_chacha_*` tests.

The extractor removes page headers, joins hexadecimal lines, verifies the
published octet counts, and preserves operation order. Its input SHA-256 pins are:

| Source | SHA-256 |
| --- | --- |
| `rfc8448.txt` | `6564d1376d1ec744fc7a9993da15ebc1b9be361908b166091f47ef605c537fba` |
| `rfc9001.txt` | `3bbaecdf5afd278052a2c48348ce118c4ff8d0cf6b9915549858171b3f98a591` |

To reproduce, save the RFC Editor's `/rfc/rfc8448.txt` and `/rfc/rfc9001.txt`
responses in one directory, then run from the repository root:

```sh
python3 scripts/test/provider_vectors.py /path/to/rfc-sources
python3 scripts/test/fixtures.py
```

The workspace fixture gate covers these files and their adjacent `SHA256SUMS`.
